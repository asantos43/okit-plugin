## [0.4.0] - 2026-11-07

### Added

- Manage several subscriptions: Claude Code and Codex accounts with stable ids, editable labels and their own config folders (`okit-plugin account add|list|remove|rename`, `install`/`uninstall --account <id>`), with quota readers, slots and sessions isolated by account. / Gerenciar várias assinaturas: contas do Claude Code e do Codex com ids estáveis, nomes editáveis e pastas próprias (`okit-plugin account add|list|remove|rename`, `install`/`uninstall --account <id>`), com leitores de cota, vagas e sessões isolados por conta.
- Suggest an editable account configuration folder from the account name for Claude Code and Codex, use the same default for empty API folders and provide localized collision guidance. / Sugerir uma pasta de configuração de conta editável a partir do nome da conta para Claude Code e Codex, usar o mesmo padrão para pastas vazias na API e fornecer orientação localizada sobre conflitos.
- Choose the account by policy (eligibility, weekly pacing, session pinning, review preference) with reasons in English and Portuguese, and stop a launch for a logged-out account before any process starts, with a structured refusal. / Escolher a conta por política (elegibilidade, ritmo semanal, sessão fixa, preferência de revisão) com motivos em português e inglês, e parar um lançamento para conta sem login antes de iniciar qualquer processo, com recusa estruturada.
- Add the token-protected loopback `okit-plugin config ui` page: bilingual settings with reviewed atomic saves, batch resets, account actor tables and safe closing. / Adicionar a página local `okit-plugin config ui`, protegida por token: ajustes bilíngues com salvamento atômico revisado, redefinição em lote, tabelas de atores por conta e fechamento seguro.
- Add the **Accounts** tab to the configuration page: list, add, rename and remove accounts (removing keeps the folder, the login and the history), with the same validation as the CLI. / Adicionar a aba **Contas** na página de configuração: listar, adicionar, renomear e remover contas (remover mantém a pasta, o login e o histórico), com a mesma validação da CLI.
- Add a simplified account login: the exact copyable command, a **Terminal** button that opens the client's own login in the account's folder (Linux terminals, macOS `osascript`, Windows PowerShell; proven with stub terminals on Linux only) and **Check login**; the plugin never reads, types, copies or prints credentials. / Adicionar um login de conta simplificado: o comando exato para copiar, um botão **Terminal** que abre o login do próprio cliente na pasta da conta (terminais do Linux, `osascript` no macOS, PowerShell no Windows; provado só com terminais falsos no Linux) e **Verificar login**; o plugin nunca lê, digita, copia nem imprime credenciais.
- Add the optional Claude Code panel: a board of accounts, running, recent and launchable work with quota bars and reset times, fed by the read-only `panel-state --json --client <claude|codex>` document, installed with `install --panel`. / Adicionar o painel opcional do Claude Code: um quadro de contas, execuções em andamento, recentes e lançáveis com barras de cota e horários de reinício, alimentado pelo documento somente leitura `panel-state --json --client <claude|codex>`, instalado com `install --panel`.
- Offer the optional Claude Code panel at the end of successful `install` and `update` runs ("Install the optional panel?"; interactive terminals only); without a terminal, print a later hint instead; `--no-panel` skips both. / Oferecer o painel opcional do Claude Code ao final de execuções bem-sucedidas de `install` e `update` ("Install the optional panel?"; somente em terminais interativos); sem terminal, imprimir uma dica para instalar depois; `--no-panel` pula ambos.
- Tell the person in plain words when a quota-blocked subscription can launch again (`quota_notice`). / Avisar a pessoa em palavras simples quando uma assinatura bloqueada por cota volta a poder lançar (`quota_notice`).
- Answer "is it ready to launch executors?" in `okit-plugin doctor` and `env_report`, and make `doctor` a command (`--client`, `--verbose`, `--locale`) that reads the whole installation, one row per check with a Fix line, without writing anything. / Responder "está pronto para lançar executores?" no `okit-plugin doctor` e no `env_report`, e fazer do `doctor` um comando (`--client`, `--verbose`, `--locale`) que lê toda a instalação, uma linha por verificação com linha de correção, sem escrever nada.
- Prove the install on this machine: a self-check after `install` and `update` (command in each shell, status bar and hook commands, quota reading, PATH, the MCP server and its control API), register the MCP server in the client, offer optional daemon autostart in `setup`, and add opt-in container checks (Debian, Fedora, Alpine). / Provar a instalação nesta máquina: autoverificação depois de `install` e `update` (comando em cada shell, comandos da barra de status e dos hooks, leitura de cota, PATH, servidor MCP e sua API de controle), registrar o servidor MCP no cliente, oferecer inicialização automática opcional do daemon no `setup` e adicionar verificações opcionais em contêineres (Debian, Fedora, Alpine).
- Add a local control API to the MCP server (private socket or named pipe, token per call, size and connection limits). / Adicionar ao servidor MCP uma API de controle local (socket privado ou pipe nomeado, token por chamada, limites de tamanho e de conexões).
- Add the output review (CLI and MCP output inventory with English and pt-BR mock-ups) and report the real statusline-collector invocation. / Adicionar a revisão de saídas (inventário das saídas da CLI e do MCP com mock-ups em inglês e pt-BR) e informar a invocação real do statusline-collector.
- Open the installed Claude Code panel when a session starts (`panel.autoOpen`, on by default; set it to false in `config.json` to turn it off; `/okit-panel` still toggles the pane). / Abrir o painel instalado do Claude Code ao iniciar a sessão (`panel.autoOpen`, ligado por padrão; defina como false no `config.json` para desligar; `/okit-panel` continua alternando o painel).
- Color panel quota rows and terminal `doctor` percentages at 50% and 20% remaining, preserving text markers and plain text with `panel.color=false`, `NO_COLOR` or pipes. / Colorir as linhas de cota do painel e os percentuais do `doctor` no terminal nos limites de 50% e 20% restantes, preservando marcadores de texto e texto sem cores com `panel.color=false`, `NO_COLOR` ou saídas canalizadas.
- Add the shared `/okit-config` skill and `config_ui_open` MCP tool to open or reuse the protected configuration page from Claude Code, Codex or opencode without blocking the session. / Adicionar a skill compartilhada `/okit-config` e a ferramenta MCP `config_ui_open` para abrir ou reutilizar a página protegida de configuração pelo Claude Code, Codex ou opencode sem bloquear a sessão.

### Changed

- Build every client and system for x64 and arm64 (eighteen assets plus the checksums); the installers refuse any other system/architecture pair and list the six supported ones. / Gerar cada cliente e sistema para x64 e arm64 (dezoito artefatos mais os checksums); os instaladores recusam qualquer outro par de sistema/arquitetura e listam os seis aceitos.
- Present the output of `install.sh`, `install.ps1` and `okit-plugin install|update|uninstall|setup` through one presenter: the same numbered steps on every system, one language per run and the exact next commands. / Apresentar a saída de `install.sh`, `install.ps1` e `okit-plugin install|update|uninstall|setup` por um único apresentador: os mesmos passos numerados em todos os sistemas, um idioma por execução e os próximos comandos exatos.
- Move the core functions into one operations registry and generate the MCP tools from it; the old CLI commands are removed, so people have five commands (install, update, uninstall, setup, doctor) and the assistant uses MCP tools, with nothing the model reads telling it to run a kit command. / Mover as funções do núcleo para um único registro de operações e gerar as ferramentas MCP a partir dele; os comandos antigos da CLI foram removidos, então a pessoa tem cinco comandos (install, update, uninstall, setup, doctor) e o assistente usa ferramentas MCP, sem nada que o modelo leia mandando rodar um comando do kit.
- Make the status bar collector store only what the client sent, with the instant it arrived, and read the quota out of it in the core. / Fazer o coletor da barra de status guardar apenas o que o cliente enviou, com o instante em que chegou, e ler a cota a partir disso no núcleo.
- Modernize the configuration page with accessible tabs, persistent selection, collapsible sections with field counts, unsaved-edit indicators and light and dark themes. / Modernizar a página de configuração com abas acessíveis, seleção persistente, seções recolhíveis com contagem de campos, indicadores de edição não salva e temas claro e escuro.
- Translate skills, adapter messages, scripts and installation text to English, keeping the existing English skill triggers. / Traduzir skills, mensagens dos adaptadores, scripts e texto de instalação para inglês, mantendo os gatilhos de skills em inglês que já existiam.
- Make the installer follow the client the person chose: the model setup covers only the clients being installed (a Claude-only install used to ask for Codex and OpenCode models and never for Claude's), asks Claude Code's three work classes with the current model as the default, and ends with an aligned self-check table, a Notes group and a Next group with one copyable line that loads the new command in the current shell. / Fazer o instalador seguir o cliente escolhido: o setup de modelos cobre só os clientes instalados (uma instalação só do Claude pedia modelos do Codex e do OpenCode e nunca os do Claude), pergunta as três classes de trabalho do Claude Code com o modelo atual como padrão e termina com uma tabela de autoverificação alinhada, um grupo de Notas e um grupo Próximo com uma linha copiável que carrega o novo comando no shell atual.
- Align the panel's quota rows, mark low quota and show local reset times with compact durations. / Alinhar as linhas de cota do painel, marcar cota baixa e mostrar a renovação em horário local com durações compactas.
- Default actors, status and profile selection to the calling client, make other clients informational and not launchable, identify the client in MCP registrations, keep slots and caps shared across clients, and explain the Director's role in role skills and docs. / Usar o cliente da sessão por padrão para atores, status e seleção de perfil, tornar outros clientes informativos e não lançáveis, identificar o cliente nos registros MCP, manter vagas e limites compartilhados entre clientes e explicar o papel do Diretor nas skills de papéis e na documentação.

- Keep a path-shaped permission-denied reason intact and translated, and keep untranslated person names byte for byte. / Manter intacto e traduzido o motivo de permissão negada com forma de caminho, e manter nomes de pessoas sem tradução byte a byte.
- Polish the installer after a real run with model confirmation for selected clients, one terminal reader shared across questions, an always-printed Models result row, wrapped panel explanations and recorded reused command links so uninstall removes them while keeping foreign commands and shared accounts, and correct older-install guidance to request a plugin update and client restart with smoke installation checks covering all seven shared skills. / Refinar o instalador após uma execução real com confirmação de modelos para os clientes selecionados, um único leitor de terminal compartilhado entre perguntas, uma linha de resultado Modelos sempre impressa, explicações do painel com quebra de linha e registro dos links de comando reutilizados para removê-los na desinstalação preservando comandos de terceiros e contas compartilhadas, e corrigir a orientação para instalações antigas pedindo atualização do plugin e reinício do cliente com verificações de instalação smoke cobrindo as sete skills compartilhadas.

### Fixed

- The atomic write of `daemon.pid.json` no longer fails with `EPERM` on Windows: `writeJsonAtomic` waits out a rename refused while a reader holds the file open, with a budget of its own (`ATOMIC_WRITE_RETRY`) derived from the transient one of the lock instead of the eight attempts the lock spent.
- The end-of-run write of a spawned run is retried when Windows refuses the rename: `writeJsonAtomic` keeps the filesystem code in `cause`, and the retry in `src/spawn-process.js` looked only at `error.code`, so the first refusal ended the run unwritten and a failing client never reached `failed`. The retry now reads the code from `cause`, and the spawn tests derive their deadline from the exported retry budget instead of a flat 2 s.
- `withLock` treats a mkdir refused by Windows with EPERM, EBUSY or EACCES as a lost attempt instead of a fatal error: the contender tries again until its own timeout, and the timeout message now names the last refusal code (`last refusal: EPERM`), so a lock folder another process is taking or removing no longer ends the run with a raw code.
- A lock queue can no longer report a lock that nobody can take. The release in `withLock` now waits out EPERM/EBUSY like every other call of the lifecycle: it removes the owner file the holder has just written and closed, the file Windows and the antivirus behind it refuse to delete while they hold a handle, and a refusal there ended the bump *and* left the folder behind holding the owner of a process that was now gone and younger than `staleMs` — longer than every caller's timeout — so every contender behind it reported `Lock … is held by pid N … after 10000 ms`. A release that answers ENOTEMPTY (the folder was emptied but a contender wrote an entry back before the `rmdir`) or ENOENT (another contender removed it first) is a release, not a failure: the entry that answered is the only evidence every waiter of that folder reads, so retrying would take a lock from a live owner, and it is left alone. A refusal of the rename that moves a dead owner's claim out is likewise given up as one attempt instead of thrown out of `acquireLock`, so a takeover outlives a busy disk instead of ending the run on a raw code.
- The wait the state tests give a contender (`BUMP_WAIT_MS`) is sized from the retry budget a bump can spend times the widest queue instead of being a flat 10 s: with `owner` and `release` each refused for the whole budget one bump costs ~580 ms, and twenty queued contenders cannot fit that in ten seconds, which is how a queue of live contenders reported a lock "held by pid N" while every one of them was working and releasing.
- A stale lock takeover can no longer leave a folder nobody can claim: while it holds the dead owner's claim and has not written its own, the folder has no owner file at all, and the rename that moved the claim out refreshes the mtime that `claimFolder` judges an owner-less folder by, so any failure in that window — a claim read Windows refuses, a restore rename it still refuses, the removal of the claim — left a folder that stayed unclaimable for `staleMs`, longer than every caller's timeout, and every other process on the root then failed with `Lock … is held by an unknown process`. The owner write now waits out EPERM/EBUSY as every other call does, every way out of that window puts the dead owner's evidence back (the claim is renamed home, or, when Windows still refuses to move it, its bytes are written back with the same exclusive create that made it a claim), and a refusal that outlives every retry restores the claim and lets the poll loop judge again instead of throwing out of `acquireLock`.
- `src/spawn-process.js` retries the read and the write that end a run while Windows answers EPERM/EBUSY, and `renameWithRetry` in `src/state.js` waits out those codes with a pause that grows instead of a flat 10 ms. The end of a run was written once: a refusal, however short, was reported on stderr and never written again, so the run file kept `status: live` and the run was never seen to finish.
- `src/daemon.js` takes its lock once instead of waiting 300 ms for it: `timeoutMs: 300` is a budget between attempts, not a bound on the wall clock, and the deadline is only read after two filesystem calls, so on a Windows disk a second daemon on the same root polled about a dozen times and refused after 2274 ms. A lock left behind by a crashed daemon is still taken over on that first try, since the takeover runs before the deadline is looked at.
- A stale lock takeover no longer acts on a verdict read before an earlier lock was replaced, so a lock that is fresh but has no `owner.json` yet is never moved aside, and an owner that loses its folder before the owner file lands takes the lock again instead of failing.
- The stale-lock takeover claims the folder in place, renaming the dead owner's `owner.json` out of it instead of moving the folder aside, so the window where the folder could not be given back — after which the displaced owner's release deleted the live lock of whoever had taken the path — no longer lets two children into the same section.
- `test/state.test.js` forks itself through `fileURLToPath(import.meta.url)`, since the path part of a URL is `/C:/...` on Windows and `fork` could not start the child from it, and a forked child keeps its stderr, so a rejection now carries the last 2 KB of what the child said instead of only "child exited with 1".
- `test/spawn-process.test.js`'s `until` keeps the last value and the last error a poll saw and names both in the timeout, so the two run-file tests that fail only on Windows report what the run file said or why it could not be read.
- `src/spawn-process.js` reports every failure of the run file it used to swallow: the first write, the read-back before the record on exit, a run file that is gone by then, and the write of the record, each one line `okit: run file <path>: <message>` on stderr; the first write still throws, as before.
- Three tests spelled an expected path as posix text while the code builds it with `node:path`, so they failed on Windows and nowhere else: `configRoot` is expected as `resolve('/tmp/somewhere')`, the systemd, cron and launchd plans in `test/autostart.test.js` compare against `join('/home/u', ...)` and the `rm -f`/`launchctl` lines built from it, and `test/cli.test.js` ends the written path with `join('systemd', 'user', 'okit-daemon.service')`.
- `test/adapter-claude-code.test.js` removes each temporary folder once: `root` pushed into both the roots and the temps list, so the cleanup ran two concurrent recursive removals over the same tree and Windows answered `EPERM` from `rmdir` on a folder the other one was still emptying. The list is deduplicated and the removal asks for retries, with a test that fails on every platform if a folder is listed twice.
- A forked child of `test/state.test.js` writes the code, the message and the stack of a failed bump with `writeSync` on stderr before it exits, and the parent names how many milliseconds the child lived, so the wider takeover race reports why it died instead of only "child exited with 1".
