# Configuration

Configuration combines built-in defaults with choices saved in the state root.

`language` chooses the language for commands and MCP tools: default `en`, with `pt-BR` also accepted. Set Portuguese once with `okit-plugin config set language pt-BR`; `okit-plugin config unset language` restores English. An explicit `--locale` or MCP `locale` takes priority for that call. Unsupported languages are refused with a message in both languages.

<a id="read"></a>
## Inspect and change

Use `okit-plugin config show`, `okit-plugin config get limits.global`, `okit-plugin config set limits.global 3` and `okit-plugin config unset limits.global`.
The CLI validates only the schema keys below; other technical options are config.json overrides, not accepted by config set. Profiles and detection merge by client/class/field; other consumers may merge groups by their own rules. Back up before editing.

## CLI-supported keys

client is a configured client; class is simple, normal or hard. Each field default appears in the inventory. Without limits.clients overrides, limits.global applies; profiles.<client>.<class> accepts only null to disable. limits.perClient is a legacy alias of limits.global.

## Options outside the central defaults object

The code also reads `daemon.intervalSeconds` = 60, `daemon.logKeepDays` = 14, `daemon.maxTurns`/`daemon.maxMinutes` = absent ([daemon](../../src/daemon.js)); `orders.retentionDays` = 90 ([orders](../../src/orders.js)); `configuredClients` = names of saved profile entries ([profiles](../../src/profiles.js)); `setup.done.at` = absent until setup confirmation ([setup](../../src/setup/setup.js)).
Interval controls the loop; retention controls log/order removal; maximums bound runs; configuredClients scopes configured clients; setup.done records completion without proving account access. Default model names are candidates, not proof of access. Unknown/expired allowance blocks environment launch policy, separate from the daemon check.
