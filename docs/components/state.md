# State on disk

![okit-plugin: Components](../images/banners/components.svg)

The plugin stores configuration, work and observations in the person's state directory.

<a id="root"></a>
## Root and files

The default root is ~/.okwork; OKWORK_HOME replaces the entire directory (it does not append .okwork). Relative paths below start at this root unless stated otherwise. Installation payloads use a separate directory.

| Path | Contents |
| :- | :- |
| `config.json` | Overrides of defaults, profiles and completed-setup record |
| `project.json` | Project name/path used in references |
| `inbox.json` | Version, sequence and work items, status, ownership/history and metadata |
| `orders.json` | Global/project instructions, expiry, revocation and history until retention |
| `templates.json` | Recurring demands, schedules, rules and last run |
| `quota/<client>.json` | Remaining percentage, source, timestamp and known windows; readers choose between automatic and manual; valid JSON of another type is no reading, a file that is not JSON makes the status fail |
| `quota/claude-code-statusline.json` | The status bar JSON of the client as it came, with the instant it was received; the collector writes it and the core derives the quota reading from it |
| `runs/<runId>.json` | Slot status, client and start/end times; process launches also record PID and outcome |
| `runs/<runId>.out` | Process launcher stdout/stderr when no other log directory is supplied |
| `locks/config.lock/owner.json`, `inbox.json.lock/owner.json`, `orders.json.lock/owner.json`, `templates.json.lock/owner.json`, `runs.lock/owner.json` | Writer lock owner, PID and timestamp; temporary claim files coordinate recovery |
| `control/<pid>.json`, `control/<pid>.sock` | Record and socket of the [control API](control-api.md) of a running MCP server; private to the user |
| `daemon.lock/owner.json` | Exclusive daemon loop lock |
| `daemon.pid.json`, `daemon.paused`, `daemon.stop` | Loop owner and persisted pause/stop controls |
| `logs/<date>.jsonl` | Daemon decisions and retention purges |
| `logs/smoke/smoke-<runId>.jsonl`, `logs/smoke/smoke-<runId>.log` | Client scenario events and readable report |
| `claude-statusline.original` | Status bar backup before consented registration |
| `autostart/okit-daemon.cron`, `logs/daemon.out` | Cron plan and daemon output for that plan |

<a id="installation"></a>
## Outside the state root

Default payload destination: XDG_DATA_HOME/okit-plugin or ~/.local/share/okit-plugin on Linux; ~/Library/Application Support/okit-plugin on macOS; LOCALAPPDATA/okit-plugin or ~/AppData/Local/okit-plugin on Windows. install.destination overrides it.
There, install.<client>.json records current payload, checksum, previous version, link, autostart and status bar; install.json is the legacy record. <version>-<client>/ holds code; managed-path.json tracks only managed PATH changes. A record or a PATH state with a field of the wrong type is refused (exit 2) with the way out: remove the file and run `okit-plugin install`. The default link directory is ~/.local/bin or ~/AppData/Local/bin on Windows; configuration can override it. Hooks, skills and role blocks live in [client roots](adapters.md).
Autostart also registers ~/.config/systemd/user/okit-daemon.service, ~/Library/LaunchAgents/com.okit.daemon.plist or a Windows task, according to platform and plan.

<a id="integrity"></a>
## Integrity and removal

JSON writes use a temporary file, sync and rename; locks use directories with owners and dead-process recovery. Missing files allow a fallback; invalid JSON does not silently become empty configuration. Do not remove active-process locks. Ask your assistant to locate the effective state (`env_report`) and to inspect the settings (`config_get`). The diagnosis only reads: it opens `config.json`, `inbox.json`, `orders.json`, the records of the control folder, `daemon.pid.json` with the log of the daemon, the file of the autostart plan and the `package.json` of the plugin (the minimum Node version); it never writes, never removes the record of a dead process and never changes the installation.
Update preserves state. Uninstall preserves it by default; --purge --yes requires no remaining clients and deletes the root. Back up history before removal.

<a id="measurements"></a>
## Optional usage measurements

Ask your assistant about the saved measurements: `telemetry_status` shows what is saved and where, and `telemetry_export` exports them from a date you name. Recording and sending start off and require separate requests. Nothing is recorded by default. Only counts, durations, states, helper names and a hashed project are saved in atomic OTLP/JSON files; prompts, file contents, demand text and paths are dropped. Files are pruned by age and total size. When kit is configured, its local destination and retention are reused unless overridden. Sending occurs only during export after separate opt-in, contains aggregate counts only and requires HTTPS (HTTP allowed only for localhost). Addresses and headers are never logged.
<a id="trajectories"></a>
## Optional run recordings
Recording is off by default, with no recording files created; the consent is the setting `trajectory.enabled` of `config.json`. When it is on, messages, available thoughts, tool inputs/results and usage are saved only on this computer, and turning it off stops future recording and keeps existing files. Process completion and practice executor/reviewer attempts record available content, model, effort and role; each reviewer carries the executor attempt reference. Native delegation records the handoff; completion content is available only when supplied as a transcript to the adapter. Unknown metadata values are null; unavailable usage is omitted, never estimated. Per-step usage is summed only where supplied; missing usage is not treated as zero. `trajectory_show` shows a saved run step by step, with the failed tools and the tokens of each step; the file stays on this computer and nothing is sent anywhere.
Files under trajectory/ use atomic writes, a shared retention lock, age/size retention, and visible truncation markers. Readers skip empty JSONL records before parsing, make no step from a row without text, calls, results, usage or other data, and strip one leading UTF-8 BOM, including file capture. Readers and default PEM redaction scan repetitions linearly; capping caches step sizes without serializing whole steps. Patterns never receive strings over the file limit. JSON keys including `__proto__` survive as own data properties; unknown fields go to `extra` where supported. Call IDs resolve within their step and may repeat across steps. JSON depth is bounded at 100 object/array levels; deeper content becomes `[truncated: too deep]`. Counter overflow keeps separate steps and leaves the total null. Configured patterns hide matching secrets; review recordings before sharing. Process output in runs/ stays separate. The writer uses `ATIF-v1.4`; readers accept `ATIF-v1.0` through `ATIF-v1.7`, including old files. The Director checks Harbor **0.22.0** separately from Node tests. Capture updates step totals after additions and counts added usage once. Capped files retain available totals and report retained step counts. Seeded fuzz covers empty records, prototype keys, repetitions, hostile timestamps, incomplete PEM and capture additions; timestamps over 64 characters are repaired. Saving again merges the runs of the session: within each [source, timestamp] group, exact message/call-ID occurrences match before compatible prefixes or known cut versions, then group position breaks ties. Each backbone slot matches at most one occurrence; matching across groups requires a known cut version on at least one side, so intact clockless and timestamped prefixes stay separate. Incompatible identities remain separate; without identity, ambiguity can retain duplicates. Distinct events without a common clock are preserved in canonical order, which need not be chronological. The longer sequence is the backbone; equal lengths use canonical JSON. Unmatched steps append after a budget of 8 × combined step count candidate/prefix work units; cut detection is cached. Step numbers are display order only. The latest observed timestamp is retained before capping and wins scalar metadata; clock ties use scalar identity metadata, independent of cut step content. Maps keep keys from both captures and child runs merge by trajectory ID. Before reading an old file, saving checks its size against the per-file and total byte limits; an oversized, unreadable or invalid file moves to a unique `<file>.corrupt-<timestamp>` backup (up to 1000 exclusive-name attempts; exhaustion refuses, preserves the bad source and releases the lock), backups stay out of the session list and share the retention of the recordings (age, total bytes, per-file bytes and the file count budget), and a failed move removes the bad file or refuses in plain words. The shared lock covers reading, merging, writing and pruning, and a lock timeout gives a clear refusal; `exportTrajectory` still reads outside that lock.
Strict Harbor input retains its version, nulls, absent fields, empty collections and steps, metadata, token arrays and subagents. Numeric and boolean fields require JSON numbers and booleans; numeric strings and integers outside JavaScript's safe range are repaired. The differential counts raw unsafe integer literals and skips only their strict identity check. Stored step totals change only by the number of steps normalization adds/removes. Tool arguments are objects. Invalid result references move to the matching call's step or become null. Failures use `step.extra.failed_calls` or orphan indices in `step.extra.failed_results`; old `content.is_error` stays readable. Non-agent usage folds into a preceding agent that permits metrics, or becomes an agent step. Missing local images become `[image: path]` when saving; paths containing `://` remain images. Pure normalization leaves paths alone. The viewer renders text, images and `→` subagent references; empty messages display “not available”. Invalid timestamps retain `extra.original_timestamp`; unknown fields move to `extra` where supported. With Harbor's Python, emit fixtures using `scripts/check-atif.py --emit <folder>` or mutate with `--mutate <folder> --n 2000 --seed 1` (repeat seeds 2, 3). Run `node scripts/check-atif.mjs --diff <folder>`, then `scripts/check-atif.py <folder>/out` with Harbor. Verdicts record lax/strict acceptance; differential and fuzz share a conservation oracle: safe nonnegative usage moves once, metadata stays with its step, overflow stays separate, and totals match steps except stored totals retained for identity/capped files. Mutations cover numeric strings, oversized integers, optional null/absent fields, empty steps, totals and image paths. Client samples use `node scripts/check-atif.mjs <folder>`; seeded producer checks use `--fuzz <folder> --n 300`. Harbor runs separately from Node tests.
Merge limits: only a cut in the message permits incompatible-message or cross-group matching; a cut in reasoning or another payload preserves intact message identity. Before capping, `extra.trajectory_merge_start` and `extra.trajectory_merge_clock` retain the complete clock range; a null start means unknown. Complete, strictly disjoint ranges add stored usage (8 + 15 stays 23 even at 750 bytes); overlapping, absent or legacy ranges keep conservative known lower bounds rather than guess overlap. Lossy persistence can erase messages, occurrences, the ordering backbone and metadata maps: different histories can then have the same saved representation, so arbitrary save-order equality and replay equality are not guaranteed after actual loss, and overlapping totals may depend on order. Without a cap, both save orders agree, distinct identities survive and replay is idempotent. The fixed-seed property checks 300 real save pairs in under 3 seconds; after actual loss it relaxes only full-file equality and replay equality, still requiring scalar metadata stability, valid size-bounded files and nondecreasing replay usage. Separate regressions require full equality and exact usage for the disjoint-clock example.
