# Instalar e começar

![okit-plugin: Guia do usuário](../images/banners/guide.svg)

Instale o plugin para seu cliente de IA e confirme que ele consegue ver seu ambiente.

<a id="install"></a>
## Instalar

1. Execute `node --version`. Espere `v20` ou mais recente; instale o [Node.js](https://nodejs.org/) se necessário. Tenha Claude Code, Codex ou opencode instalado e com login feito.
2. Baixe o instalador da [versão](https://github.com/asantos43/okit-plugin/releases/latest) desejada e leia antes de executar. No Linux/macOS:

   ```sh
   curl -fLO https://github.com/asantos43/okit-plugin/releases/latest/download/install.sh
   ```

   Espere `install.sh` na pasta atual. No PowerShell do Windows:

   ```powershell
   Invoke-WebRequest https://github.com/asantos43/okit-plugin/releases/latest/download/install.ps1 -OutFile install.ps1
   ```

   Espere `install.ps1` na pasta atual.
3. Nessa pasta, execute `sh install.sh --client codex` no Linux/macOS ou `./install.ps1 --client codex` no PowerShell. Troque `codex` por `claude-code` ou `opencode` para seu cliente. Espere um pacote verificado, um destino de instalação e um resumo do registro. Siga as instruções de ativação do cliente impressas pelo instalador; no Codex, a ativação usa `/plugins`.
4. A instalação e as atualizações oferecem o setup de modelos para os clientes selecionados nesta instalação. O Claude Code também pergunta por tarefas pequenas, do dia a dia e complexas, com haiku, sonnet e opus entre as opções disponíveis. Cada cliente tem uma lista numerada seguida de três perguntas curtas; a escolha atual é o padrão. Uma classe com opção única aparece explicada na tabela de confirmação. `--client all` revisa todos os clientes selecionados; o comando avulso `okit-plugin setup` continua revisando todos os clientes detectados. Se nenhum modelo ativo for detectado, siga [modelos e cota](models-and-quota.pt-BR.md).

   A saída agrupa Escolhas, passos numerados da instalação, linhas alinhadas da autoverificação, Notas e, por último, Próximo. Em “Execute agora:”, copie o comando na linha própria para ativar o comando instalado neste terminal (por exemplo `. '/home/voce/.zprofile'`). Ele indica o perfil que contém o bloco do PATH; fish e PowerShell mostram o equivalente. Ou abra um terminal novo e reinicie o cliente de IA. O instalador não pode mudar o PATH do terminal que o iniciou. Execuções sem terminal mostram orientações sem perguntas.

   Ao final, o `okit-plugin setup` interativo oferece iniciar o serviço em segundo plano com a máquina. O padrão é não; `--defaults` nunca instala a inicialização automática. `okit-plugin uninstall` a remove.
5. Peça ao seu assistente: “Qual é o ambiente?” (ele chama `env_report`). Espere o cliente, modelos ativos confirmados, cota, vagas livres para ajudantes e pastas. Itens desconhecidos continuam desconhecidos e incluem instruções de correção.

O instalador também registra o servidor MCP do plugin, chamado `okit`, no Claude Code e no Codex com o próprio comando de cada cliente (`claude mcp add --scope user okit -- node <instalação>/src/mcp/server.js` / `codex mcp add okit -- node <instalação>/src/mcp/server.js`). O OpenCode ainda não é registrado pelo instalador. Ele lê a entrada antes: uma que já é nossa fica como está, uma que aponta para a versão substituída é trocada, e uma entrada chamada `okit` que não é nossa é mantida com um aviso. Só é nossa uma entrada de um servidor stdio cujos próprios argumentos são o nosso caminho, inteiro: no Claude Code, o campo que nomeia o tipo do servidor (`Type`) tem de ser `stdio` e o campo de argumentos tem de nomear o nosso caminho; um servidor de outro tipo, e um cabeçalho que contém uma linha que parece o campo de argumentos, não são nossos e são mantidos. O Codex responde com JSON (`mcp get --json`), onde a fronteira de cada argumento é exata: a entrada é nossa quando o transporte é stdio e o `args` dele tem exatamente um elemento, o nosso caminho, inteiro. Uma entrada que o cliente mostra em outro escopo que não o configurado também é tratada como não nossa e é mantida, mesmo quando os argumentos dela nomeiam nosso caminho. O Codex é a exceção: ali o instalador só adiciona a entrada quando ela falta, porque o cliente não diz onde a entrada fica (o `mcp get` dele procura, nas pastas acima da que ele roda, a configuração de um projeto confiável, então pode mostrar a entrada desse projeto); uma entrada que já está lá nunca é trocada nem removida pelo instalador, e o aviso mostra os comandos para rodar à mão. O comportamento do Claude Code é o de cima. Quando a pasta da instalação tem espaço no caminho, o texto do Claude Code não diz se a entrada é nossa ou uma de fora cujos argumentos foram divididos, então o instalador só adiciona a entrada que falta e deixa a que já está lá, mostrando os comandos para rodar à mão; no Codex o JSON guarda a fronteira de cada argumento, então um caminho com espaço é nosso ali. Se o cliente recusar, a instalação continua e o aviso mostra o comando para rodar à mão; se o cliente não estiver na máquina, os mesmos comandos aparecem com os outros passos manuais. Uma entrada que o cliente não consegue ler (o cliente falha, estoura o tempo ou responde outra coisa) também é um aviso: nada é escrito, porque a entrada do cliente pode não ser nossa. Rode o instalador de novo para tentar de novo: uma instalação que já está lá lê sua entrada e a adiciona quando ela falta. Os comandos do cliente rodam a partir da pasta da instalação. O `mcp get` do Claude Code diz o escopo da entrada que mostra, e uma entrada em outro escopo nunca é tocada. O Codex não diz o escopo e pode mostrar a entrada de um projeto confiável acima da pasta da instalação, então no Codex o instalador só adiciona a entrada, nunca troca nem remove uma, e mostra os comandos para rodar à mão.
A autoverificação depois da instalação prova o mesmo servidor: ela o inicia sob uma pasta de estado temporária (o seu estado nunca é tocado), pergunta se ele responde e depois pergunta à API de controle dele uma chamada de ferramenta; um servidor que não responde faz a instalação falhar com o comando para rodar de novo.
O instalador e `setup --again` compartilham o assistente. Após cada escolha de modelo, ele pergunta o esforço, mostrando os valores aceitos e o padrão atual ou proposto; uma resposta vazia mantém esse padrão. Claude Code e Codex oferecem `low`, `medium`, `high`; OpenCode oferece `high`, a interseção entre as capacidades do adaptador e o schema dos perfis. Os três clientes suportam esforços. Um cliente sem esse suporte pula a pergunta e a coluna. A confirmação usa colunas alinhadas no terminal para trabalho, modelo e esforço; a revisão dos modelos atuais também mostra o esforço. Modelos e esforços são salvos juntos somente após a confirmação.

Na reinstalação, um comando do plugin que aponta para uma instalação antiga ou legada é redirecionado para os arquivos instalados. “Já está no seu PATH” significa que o comando resolve para esta instalação. Um comando alheio é preservado e a saída informa o comando exato a executar. Quando o PATH ou um perfil do shell muda, siga o comando de recarga ou abra um terminal novo. A pasta da instalação em Notas é a pasta que contém as instalações versionadas.

`OKit (opcional)` refere-se à ferramenta OKit separada, necessária somente para o fluxo de orquestração do OKit: [INSTALL.pt-BR.md#kit-de-orquestração](../../INSTALL.pt-BR.md#kit-de-orquestração).

Quando algo não estiver certo depois, execute `okit-plugin doctor`: ele lê a instalação inteira e responde uma linha por coisa que olhou, com o comando exato que repara cada falha; nunca escreve nada.

No Claude Code, execute `okit-plugin update --client claude-code --statusline` após instalar para ativar a coleta de cota preservando a barra anterior. Espere uma prévia dos ajustes; `--no-statusline` recusa a coleta. Durante a instalação, o terminal pergunta e instalações sem terminal pulam a coleta. Os scripts baixados não aceitam essas duas opções da barra; use o comando instalado.

Após instalar o Claude Code com sucesso, o terminal também oferece o [painel opcional](panel.pt-BR.md). `--no-panel` pula a pergunta e a dica; sem terminal, aparece apenas a dica posterior. Ative depois com `okit-plugin install --panel`. `update` atualiza um painel instalado sem perguntar.

A oferta descreve o painel opcional somente para leitura ao lado da conversa: a cota restante de cada conta, o trabalho em andamento e o recente. A abertura automática, `panel.autoOpen: false` e `/okit-panel` são explicados após instalar o painel com sucesso. O painel só é oferecido para Claude Code. Passos da instalação, registro de cota, painel, modelos, kit e resumo final são blocos separados por uma linha vazia, inclusive após respostas.

O setup de modelos funciona igualmente para Claude Code, Codex e opencode. Na primeira instalação propõe modelos e pede para salvá-los (padrão Sim). Se a listagem estiver indisponível, usa o catálogo incluído, nunca uma tabela vazia. Se não houver escolhas disponíveis, pula a pergunta e explica como ativar um modelo e rodar `okit-plugin setup`; escolhas não confirmadas continuam pendentes. Ao reinstalar perfis confirmados, mostra as escolhas atuais para tarefas pequenas/do dia a dia/complexas em um bloco curto por cliente e pergunta “Revisar ou alterar os modelos? [s/N]” uma vez para todos os clientes selecionados. Não mantém as escolhas; Sim abre o assistente com os valores salvos como padrão. Cancelar mantém a configuração intacta. Sem terminal, padrões não confirmados aparecem como “Modelos sugeridos”, com `okit-plugin setup` para confirmar; escolhas confirmadas aparecem como “Modelos atuais”, com `okit-plugin setup --again` para alterar. Nenhum dos casos pergunta. Atualizações com escolhas confirmadas iguais às propostas da nova versão ficam silenciosas, com uma linha Modelos ok; propostas diferentes ou escolhas não confirmadas oferecem o setup. O resumo só informa confirmação pendente para os clientes cujos perfis ainda precisam dela.

A desinstalação remove o comando pertencente ao plugin mesmo quando esta instalação o reutilizou; arquivos de outras pessoas são preservados, e outras contas registradas mantêm o comando compartilhado.

O instalador imprime os mesmos passos numerados no Linux, no macOS e no Windows, em um só idioma (`--locale en` ou `--locale pt-BR`, depois `OKIT_LANGUAGE`, depois o idioma salvo), e termina com os próximos passos e o comando exato a rodar. Use `--verbose` para ver também os comandos que ele executa. No Windows o comando é um atalho `okit-plugin.cmd` para o PowerShell e o cmd.exe mais um atalho sem extensão para o Git Bash (o shell pelo qual a barra de status do Claude Code roda), e o terminal pode perguntar, com padrão Não, se deve permitir scripts do PowerShell para o seu usuário; `--set-execution-policy` responde sim e `--no-execution-policy` pula a pergunta. Ambas também funcionam com o `update` dos scripts. Um comando alheio é preservado, mas faz a instalação falhar com instruções de correção. A escolha de modelos só é oferecida após sucesso, nunca em dry-run ou `update --check`. Veja [INSTALL.pt-BR.md](../../INSTALL.pt-BR.md#o-que-o-instalador-imprime).

Um ajuste de `config.json` que não é válido (por exemplo `install.timeoutMs` com `0` ou com texto) é recusado por todo comando com saída 2, uma linha que nomeia o ajuste e a regra (`install.timeoutMs inválido: um inteiro de 1 a 2147483647`) e o arquivo intacto; corrija o valor, ou apague-o para usar o padrão.

Para registrar o plugin em uma conta salva do Claude Code ou do Codex, acrescente `--client` e `--account`; veja [contas](accounts.pt-BR.md#register).

Instalar/atualizar pode editar perfis do terminal ou o PATH do usuário no Windows; `--no-path` pula isso. O download verifica SHA-256 contra bytes alterados; isso não autentica a origem. A comprovação no cliente real varia por sistema: veja [provas da versão](../maintainers/RELEASING.pt-BR.md#proof-per-pair).
