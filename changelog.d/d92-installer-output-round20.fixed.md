A `config.json` whose root is not an object (`null`, a number, text, a list) is now an empty configuration for the telemetry commands too, as it already was for every other command: `telemetry status|check|export` no longer exit 1 with an error that has no kind, and `telemetry on|off|rede` write an object over it (one helper, `storedRootOf`). The input inventory scan of file reads now covers `adapters/` as well as `src/`, and classifies each read found there: the quota file of each client (`quota/<client>.json`: not JSON, empty or a folder is exit 1; valid JSON of another type is no reading and `status` goes on), the client's `settings.json` read by the role step, the `SKILL.md` and plugin files of the package, and the Codex session and opencode source readers (never a failure of `status`), each proved by a test.
