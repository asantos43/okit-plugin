The check runs only what is exactly ours: a session hook is run only when its string is exactly the installer's (otherwise a visible skip), the temporary state root receives only the allowed keys of `config.json` (`install.selfcheck.stateKeys`), the hook starts no process during the check, and the new-terminal note is said once with `--verbose` / A verificação roda só o que é exatamente nosso: um hook de sessão só é executado quando a sua string é exatamente a do instalador (senão, um pulo visível), a raiz de estado temporária recebe só as chaves permitidas do `config.json` (`install.selfcheck.stateKeys`), o hook não inicia nenhum processo durante a verificação, e o aviso de terminal novo sai uma só vez com `--verbose`. The hook and the status bar are run only when each is byte-for-byte what the installer's own writer produces (compared with its output, never parsed; the node form of the bar is no longer run), otherwise a visible skip, and a hook that differs only in the node path says to install again; the docs say the check starts your configured shell, which reads its usual startup files / O hook e a barra de status só são executados quando cada um é, byte a byte, o que o escritor do próprio instalador produz (comparado com a sua saída, nunca interpretado; a forma com node da barra não é mais executada), senão um pulo visível, e um hook que difere só no caminho do node diz para instalar de novo; a documentação diz que a verificação inicia o seu shell configurado, que lê seus arquivos de inicialização usuais. With `--no-link` there is no shim of ours in the link folder, so the bare status bar is not run and the skip says so / Com `--no-link` não há atalho nosso na pasta do link, então a barra de status pelo nome puro não é executada e o pulo diz isso.
