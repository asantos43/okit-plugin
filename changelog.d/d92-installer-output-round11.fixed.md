The installer's invariants now hold at every entry point, not only at the call site that was fixed: the standalone `setup` and `kit` use the same language order as `install` (`--locale`, `OKIT_LANGUAGE`, the saved language, English; no more mixed English and Portuguese, and a saved language that is not one is exit 2), an unknown flag is refused in the saved language because the configuration is read before the flags, the notes that belong to the whole run (SHA-256, PATH check) are said once with several clients, and the dry run of `install`, `update` (same version included) and the bootstrap script shows the same numbered steps as the real run, from one `planSteps`; a matrix test (entry points by language sources) guards it / As invariantes do instalador agora valem em todo ponto de entrada, não só no ponto de chamada corrigido: o `setup` e o `kit` avulsos usam a mesma ordem de idioma do `install` (`--locale`, `OKIT_LANGUAGE`, idioma salvo, inglês; sem mistura de inglês e português, e um idioma salvo inválido sai com código 2), uma opção desconhecida é recusada no idioma salvo porque a configuração é lida antes das opções, as notas que pertencem à execução inteira (SHA-256, verificação do PATH) saem uma só vez com vários clientes, e a simulação do `install`, do `update` (inclusive na mesma versão) e do script de bootstrap mostra os mesmos passos numerados da execução real, a partir de um só `planSteps`; um teste em matriz (pontos de entrada por fontes de idioma) protege isso.
