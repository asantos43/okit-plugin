The post-install self-check now starts the shell of your own terminal the way a new terminal does (`bash -lc`, `zsh -lc`, `sh -lc`, `fish -l -c`), with the link folder taken off the PATH, so only your profile can add it: a profile that exits early, fails or never reaches the PATH block now fails the install with the shell, the reason and the exact fix, instead of passing. The login launch is made for the shell of your own terminal only (a POSIX shell that reads `~/.profile` like `sh` does is checked as the `sh` entry; a shell outside that list, such as csh, is not launched; no other installed shell is launched), any line the launch prints may be the resolution (a greeting printed before it, or a message printed after it, does not hide it) as long as it names `okit-plugin` (another program of the link folder printed by your profile is not the resolution), the fix names the file that shell really reads at login (for zsh, `$ZDOTDIR/.zprofile` when `ZDOTDIR` is set; for fish, `$XDG_CONFIG_HOME/fish/config.fish` when `XDG_CONFIG_HOME` is set) and asks for the line to go before anything that stops that file with `return` or fails, and for any `exit` in it to go (a login file must not exit). One limit: when `~/.zshenv` sets or overrides `ZDOTDIR`, the fix names the file of the inherited environment, which may not be the file zsh really reads; the check itself is right. / A autoverificação depois da instalação agora inicia o shell do seu próprio terminal como um terminal novo o inicia (`bash -lc`, `zsh -lc`, `sh -lc`, `fish -l -c`), com a pasta do link fora do PATH, então só o seu perfil pode adicioná-la: um perfil que sai cedo, falha ou nunca chega ao bloco de PATH agora faz a instalação falhar, dizendo o shell, o motivo e a correção exata, em vez de passar. A partida de login é feita só para o shell do seu próprio terminal (um shell POSIX que lê o `~/.profile` como o `sh` lê é verificado como a entrada `sh`; um shell fora dessa lista, como o csh, não é iniciado; nenhum outro shell instalado é iniciado), qualquer linha que a partida imprime pode ser a resolução (uma saudação impressa antes dela, ou uma mensagem impressa depois dela, não a esconde), desde que nomeie `okit-plugin` (outro programa da pasta do link impresso pelo seu perfil não é a resolução), a correção diz o arquivo que esse shell realmente lê no login (para o zsh, o `$ZDOTDIR/.zprofile` quando o `ZDOTDIR` está definido; para o fish, o `$XDG_CONFIG_HOME/fish/config.fish` quando o `XDG_CONFIG_HOME` está definido) e pede que a linha venha antes de qualquer coisa que pare esse arquivo com `return` ou falhe, e que qualquer `exit` dele saia (um arquivo de login não pode sair). Um limite: quando o `~/.zshenv` define ou sobrescreve o `ZDOTDIR`, a correção diz o arquivo do ambiente herdado, que pode não ser o arquivo que o zsh realmente lê; a verificação em si está certa.
