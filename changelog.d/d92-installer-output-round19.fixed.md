An installation record (`install.json`, `install.<client>.json`) with a field of the wrong type (`linkDirectory`, `link`, `version`, `statusline`, `settings`, or any of those in the record it replaced) is now a refusal of usage (exit 2) that names the field and tells the person to remove the file and run `okit-plugin install`, in the language of the run, in `update`, `uninstall`, `status` and `install` and in the bootstrap of `install.sh` and `install.ps1`; a record that is not JSON stays exit 1. `managed-path.json` is checked the same way (wrong type: exit 2; not JSON: exit 1). The saved numbers of the telemetry (`retentionDays`, `maxBytes`, `maxFileBytes`, `batchSeconds`, `kitTimeoutMs`, `rede.timeoutMs`, `dir`) are validated by the schema of `config set` (the validator of its own is gone), so a bad value is exit 2 in every telemetry command. The input inventory now finds the files read by scanning `src/` and fails for any read that has no rule or named exclusion, and for a check of a configuration value outside the schema.
